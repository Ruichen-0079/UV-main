## Incorrect test targeting

The prior harness mistook the accessibility bounds of the hidden file input
(`Live2D ZIP`) for the visible drop zone. Its own geometry output placed
`Choose ZIP` below the WebUI viewport. A screenshot of the same packaged page
confirmed that the actual drop zone needed to be scrolled into view.

The XTest pointer helper also assumed its motion arguments were screen pixels.
On this KDE Wayland/XWayland session, requesting `(1700, 870)` resulted in
`XQueryPointer` reporting `(2550, 1305)`: a 1.5 scaling factor. The prior
destination `(1600, 1200)` therefore did not target the intended WebView.
Emitting URI data from the source alone did not prove delivery to YUVI.

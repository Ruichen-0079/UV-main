# v0.1.2 desktop UX repair and dimension audit

Local repair of `ad0024d` on `repair/v0.1.2-artifact-first`. No publication,
A1–A12 work, provider routing change, or vector migration is part of this repair.

## Reproduced presentation gaps

The running Portable's Main microphone click returned `NotAllowedError` and
rendered an instruction to use a nonexistent desktop microphone permission
setting. Wry's WebKitGTK setup enables WebAudio but installs no user-media
permission handler. The shell now handles bundled Main audio-only requests;
other origins, surfaces, and camera requests are denied. The existing live
16-kHz PCM path remains authoritative. Its AudioContext is created/resumed
inside the initiating click, before awaiting device acquisition.

Companion receives Main's gesture through BroadcastChannel, which cannot
transfer browser user activation. WebKitGTK's gesture policy is disabled only
for Companion's existing admitted speech playback. Runtime/Product speech
admission and the queue are unchanged.

Subtitle publication did not call DesktopSurfaceManager's lazy show command.
Publication now requests that existing surface and retains its latest
projection on the same subtitle bus. A subscriber-ready handshake replays it
when mounting finishes; duplicate message IDs do not restart presentation.
The existing Companion committed-text fallback remains the sole producer.

Main already renders its draft assistant state on every dispatched delta.
A React regression checks two intermediate rendered assistant states before
completion. Runtime streaming is unchanged. Live chunk/dispatch/render timing
and audible-output acceptance remain to be established on the rebuilt artifact.

True Character streaming was audited and found non-streamable under the
current ABI: the Character layer returns exactly one structured JSON decision
(`RESPOND` with text / `SILENCE` / `TERMINATE` / `NEED_COGNITION`) via a
single non-streaming `generateReply` call, so the response text does not exist
until the complete decision is validated. No fake chunking was added.

## Read-only embedding audit (2026-09-11)

* Host 8128 returned **1024** values for a real `/v1/embeddings` request.
* Process: llama.cpp b10621, Qwen3-Embedding-0.6B-Q8_0.gguf, CPU (`--device
  none --gpu-layers 0`), `--embedding --pooling last --fit off --threads 24
  --threads-batch 24 --ctx-size 2048 --batch-size 512 --ubatch-size 512
  --parallel 1 --no-ui --no-cont-batching --cors-origins localhost`, bound to
  127.0.0.1:8128. Authentication is configured; its value is intentionally omitted.
  Batch size 512 is not embedding dimensionality.
* Portable Product persisted model `local-embedding-m` has dimensions 1024,
  the full GGUF path, and endpoint http://127.0.0.1:8128/v1.
* Portable Mem0 16131 and Installed Mem0 6131 both report **Ollama**,
  `yuvi-embedding:0.6b`, **1024**, collection `yuvi_mem0_qwen3_1024_v1`.
  Their actual embedding upstream is 11434, not Product's 8128 route.
* Portable PG 55432: `yuvi_mem0_qwen3_1024_v1.vector` is `vector(1024)`,
  empty; `mem0migrations.vector` is `vector(1024)`, one metadata row;
  legacy `memories.embedding` is unbounded `vector`, empty.
* Installed PG 5432 (read-only catalog/count queries): Mem0's same 1024
  collection has two vectors. `memories.embedding` is `vector(512)` with
  three 512-dimensional vectors and one row with no embedding. Its Mem0
  migration table contains one 1024-dimensional metadata row.
* Mem0's fixed 1024 collection dates to `018e1cf` (2026-08-04). The legacy
  local MRL 512 contract landed separately in `14161d3` (2026-08-29), with
  development history `608aca8`, `17e2654`, `e48bd06` on August 28.
  Migration 010 explicitly takes the first 512 values of eligible 1024-D
  Qwen vectors and L2-normalizes them. It refuses incompatible provenance
  and mixed dimensions. That code is evidence of a real 1024-to-512 layer,
  not evidence that Mem0's collection was migrated to or from 512.

Conclusion: **A applies to current Mem0**. This is coexistence of the fixed
1024 Mem0 contract and the older local 512 MRL path, rather than proof of a
single 512 collection being recreated at 1024. **C is not supported**: active
Mem0 and its tables both expect 1024. Product and Mem0 do select different
embedding transports/models, which this audit reports without changing either.
No migration, deletion, reindex, vector rebuild, or dimension edit was performed.

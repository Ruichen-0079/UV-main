## Findings and implementation

Drag: the prior fix disabled the WebUI native handler and depended entirely on
HTML5 `DataTransfer.files`. A real GTK URI-list drag of the known-good Lumi ZIP
into the existing packaged drop zone still left Import disabled. No parser or
model-validity investigation was repeated. This localizes the observed failure to
native/WebKitGTK-to-HTML file delivery; the precise lower-level GTK failure was
not instrumented. The repair enables native handling for WebUI, records native
paths, and provides a bounded one-shot read restricted to the actual dropped
path and the WebUI window. The frontend checks drop-zone coordinates, converts
bytes to a File, and calls the existing `chooseArchive`; picker and native drop
then use the same `importArchive` and Runtime ZIP installation endpoint. There is
no second installation authority or generic filesystem-read permission.

Controls: provider tests, configuration writes and optional voice refreshes shared
one busy state, and HTTP/native waits lacked deadlines. Provider tests now have
per-provider pending state and persistent messages outside section tabs; they do
not reload configuration drafts. Optional voice refreshes run outside the write
lock and have separate error output. Writes sharing a configuration revision stay
serialized through their required configuration refresh. HTTP waits (including
response bodies) are 60 seconds, imports 120 seconds, and wrapped native commands
and sample reads 30 seconds. Timeouts explicitly say the operation may still be
completing. Transport abort is not represented as server-side cancellation.

Scroll: the old appearance panels issued native state reads every second and
unconditionally replaced React state. They now subscribe to desktop surface
changes, recover on focus, and retain equal state objects. Renderer projection
updates also compare fields. Desktop layout previously combined document scrolling
with a sticky viewport-height sidebar. At desktop widths the content pane is now
the primary scroller, with navigation resetting its scroll position. These are
identified sources of unnecessary work, not a measured claim that all WebKitGTK
stutter is eliminated. The rebuilt artifact must establish the visual outcome.

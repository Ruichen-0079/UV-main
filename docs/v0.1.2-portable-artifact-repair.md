## Reproduction and cause

An unchanged copy was launched with its public `./yuvi` entry, first with the
normal versioned state root, then a fresh explicit state root. Installed YUVI
was already running and was not stopped or changed. A third run used a separate
network namespace to remove Installed listeners from the reproduction without
interrupting them. Timings below are fresh-state observations, relative to spawn:

| Time | Observation |
| --- | --- |
| 0 ms | Public launcher starts bundled Node/launcher. |
| 94 ms | Supervisor PID 371990 publishes authenticated control and waits for Product bootstrap. |
| 101 ms | Runtime projection is stopped/none at 16121; Mem0 already defaults to 6131. |
| 461 ms | Desktop PID 372023 is running. |
| 482 ms | ConfigService push changes Runtime to 6121, STT to 9876, TTS upstream to 9880. |
| 484 ms | Desktop reports PostgreSQL unavailable/none and abandons staged boot. |
| 5096 ms | Background refresh projects Installed Runtime healthy/external, Mem0 degraded/external, STT healthy/external. |
| 5106 ms | Launcher detects external Runtime, calls stop(), sends SIGTERM to Supervisor/Desktop. |
| 5137 ms | Launcher exits, incorrectly with status zero. |

The source path is `ConfigService::open` -> generic `UserSettings::default`
-> `supervisor_config_push` -> `POST /v1/config` -> `deriveConfigFromEnv`.
The launcher environment does not constrain that later push. The five-second
timer is `DesktopSupervisor.startBackgroundRefresh`, not a Desktop fatal timer.
The actual shutdown call is the external-ownership catch in `linux-launcher.mjs`.

Independently, packaged entry skips `bootstrap()` pending the Desktop secret.
Desktop then calls `/v1/services/postgres/start` -> `ensureService` -> generic
`startManagedIfNeeded`. The private cluster has no start command until
`prepareAndStartPrivatePostgres` runs, but that was reachable only from bootstrap.
Thus PostgreSQL never starts. Without Installed network listeners, the original
lasts 120,328 ms before the launcher readiness deadline ends it. No Portable
PostgreSQL, Mem0, Runtime, STT or TTS child was started in these original runs.

Unblocking this path exposed missing `pgcrypto` and `pg_trgm` in the released
PostgreSQL payload, both required by migration 001. Real PG16 migration tests
reproduced those failures. The package validator previously checked only vector.
The UI also checked binding once, before ownership existed; it now polls the
same Desktop binding projection with a bounded loading view.

Default state remains `${XDG_DATA_HOME:-$HOME/.local/share}/YUVI/portable/0.1.2`,
or the existing explicit `YUVI_PORTABLE_STATE_ROOT`. It intentionally survives
package deletion and is shared by copies of the same product version, not by
Installed or different Portable versions. Subroots: config, data, cache, tmp,
supervisor, home. Private PG is `data/Postgres`; Mem0 is explicitly
`data/Mem0/{data,logs}` (original default was sibling `Mem0/{data,logs}`);
Runtime storage is `data/runtime-data`; STT storage is `data/local-stt`.
Supervisor per-instance logs and metadata are under `supervisor/instances`.

Authority remains: launcher owns the Supervisor/Desktop/Web process envelope;
Desktop attaches and supplies SecretStore/Product configuration; Supervisor owns
private PG and sidecar starts, readiness, ownership and shutdown. Mem0's packaged
wrapper invokes Runtime's existing migration-only entry before Mem0. Desktop
sequences PG -> Mem0 -> Runtime through the existing control API. Web rendering
waits on Desktop's binding projection. No second Supervisor, router or service
lifecycle state machine is added.

## Building locally

Use `build-linux-desktop.mjs`, `prepare-linux-daily.mjs`, and
`package-linux-release.mjs` from a clean repair commit. Internal version stays
0.1.2; put outputs in a clearly named local repair-test directory, never publish.
The Debian 12 PostgreSQL 16 distribution supplied through
`YUVI_LINUX_POSTGRES_HOME` must include contrib `pgcrypto` and `pg_trgm` built
from the same PostgreSQL source/configuration, plus pgvector. Existing migrations
are unchanged. The artifact's PostgreSQL source uses `--with-openssl`.

Verification includes Rust library tests, pnpm check, web build, repository
tests with real PG16 enabled, Portable package tests, and a bounded artifact
smoke alongside Installed YUVI. Final timings/artifact paths are in the local
handoff report, not a public release. No merge, push or tag change is intended.
